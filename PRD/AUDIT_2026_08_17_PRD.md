# Post-merge audit — PRs #61–#89

**Created:** 2026-08-17
**Status:** Open
**Baseline:** `b10993b0` → `cdb2ac7e` (HEAD at audit time; 29 merged PRs)
**Scope:** Retrospective correctness audit of the range: the Track L compatibility
work (bundling, filesystem, compat harness), the syntactic-keyword-bindings arc
(#85–#89), the continuation-escape work (#76–#79, #87), the literal-matching
redesign (#62/#63/#68), the lexer widenings (#65/#82/#83), and the standard-port
parameterization (#70/#72/#73/#76).
**Method:** seven parallel audits (macro hygiene; syntactic keyword bindings; VM
continuation escapes; lexer/reader; ports/parameters/guard; bundled libraries and
filesystem primitives; compat harness). ~150 adversarial repros, each run on both
backends with chibi as arbiter (Gauche as a second arbiter where noted). Vendored
files were checked byte-for-byte against upstream before any content review.
Baseline gate at HEAD: chibi 1226/1226 (18/18 subgroups), full Rust suite green —
none of the findings below are visible to either.

---

## The one-sentence lesson

**Every crash and every regression below sits at a seam its redesign did not
reach:** the escape work covered the four `ApplyContext` boundaries perfectly and
missed every *internal* `run_thunk` caller; the literal-matching redesign got
scope-set identity right and left both remaining spelling-based shortcuts; the
value-position rejection (#89) is sound except where `shadowed_names` was never
populated; and — repeating the 2026-08-10 audit's lesson verbatim — every library
bug is in locally written adapter lines, while every byte-identical vendored file
came through clean.

## A — Crash class: process aborts and panics

### A1 `[x]` CRITICAL — quasiquoting a syntactic keyword panics the VM

`crates/patina-vm/src/compiler/quasiquote_expand.rs:401`. The `panic!` predates
this range, but #89's fallible desugaring made it reachable from trivial input.

```scheme
(import (scheme base))
(write `(1 ,if))
;; VM          => thread 'main' panicked at quasiquote_expand.rs:401 (process abort)
;; tree-walker => Error: Internal error: quasiquote: failed to desugar unquote…
;;                (wrong error class — cps_eval/quasiquote.rs:28)
;; chibi       => clean "invalid use of syntax as value: if"
```

Same for `,when` (a macro) and `,@if`. **Fix sketch:** route the unquote
desugar failure into the #89 diagnostic ("`if` is a syntactic keyword") on both
backends instead of panicking / wrapping as an internal error.

### A2 `[x]` CRITICAL — `dynamic-wind` called as a value: escape from the body writes a register through a dead frame

`crates/patina-vm/src/runtime/vm_state.rs:2192-2217`; panic surfaces in
`set_reg_at` at `vm_state.rs:258`. After `run_thunk(state, body)`, the arm's
escape predicate is `state.frames.is_empty()` — essentially never true, since a
continuation's captured frames are never empty. The `call_value_with_probe`
safety net returns the escaped value as a normal `Ok`, so
`state.set_reg(dst, result)` runs with `dst` numbered in the now-dead caller
frame but resolved against the escape-target frame. In bounds: silent clobber of
a live register. Out of bounds: process panic.

```scheme
(define dw dynamic-wind)
(define (bad k)
  (let ((x1 1) (x2 2) (x3 3) (x4 4) (x5 5) (x6 6) (x7 7) (x8 8)
        (x9 9) (x10 10) (x11 11) (x12 12) (x13 13) (x14 14) (x15 15))
    (let ((r (dw (lambda () 0) (lambda () (k 7) 99) (lambda () 0))))
      (+ r x1 x2 x3 x4 x5 x6 x7 x8 x9 x10 x11 x12 x13 x14 x15))))
(write (call/cc (lambda (k) (bad k) 999)))
;; VM          => panicked at vm_state.rs:258:
;;                index out of bounds: the len is 4 but the index is 17
;; tree-walker => 7        chibi => 7
```

Only the *value* call path is affected — head-position `dynamic-wind` compiles
to `PushWind`/`PopWind` and is safe. #87 (calling control primitives as values)
opened this surface. **Fix sketch:** after every internal `run_thunk` in
`handle_control_primitive`, consult the same escape probe the `ApplyContext`
boundaries use (`across_reentry`), and skip the `set_reg` on escape. The
`frames.is_empty()`-era checks are dead and should be deleted.

### A3 `[x]` HIGH — continuation invoked from an after-thunk during `raise` unwinding: unbounded native recursion

`vm_state.rs:2532-2541` (`vm_raise_value` exit-wind loop) and the same ordering
in `run_wind_transition` (`vm_state.rs:2746-2753`). The wind record is still on
`state.dynamic_winds` while its after-thunk runs (truncation happens after the
loop), so an escape inside the after-thunk re-enters the same record and re-runs
the same thunk: `run_thunk → try_invoke_continuation → run_wind_transition →
run_thunk → …` with no depth guard. Head-position `dynamic-wind` suffices.

```scheme
(define r (call/cc (lambda (k)
  (guard (e (#t (list 'caught e)))
    (dynamic-wind (lambda () 0)
                  (lambda () (raise 'boom))
                  (lambda () (k 'escaped-from-after)))))))
;; VM          => fatal runtime error: stack overflow, aborting (native abort,
;;                bypasses VmError::StackOverflow)
;; tree-walker => escaped-from-after
;; chibi       => also loops, but dies with a clean "ERROR: out of stack space"
```

Chibi loops too, so the semantic choice is defensible; the defects are (a) the
uncontrolled *native* abort where chibi reports a clean resource error, and (b)
an unpinned three-way backend divergence. Normal-exit after-thunk escapes are
fine because `PopWind`/`pop_resolved_winds` pop the record *before* running the
thunk. **Fix sketch:** adopt that ordering here (pop/truncate before running
each after-thunk); pin the divergence in `backend_divergence.rs`.

### A4 `[x]` MEDIUM — suspected siblings of A2/A3 (sweep, don't spot-fix)

Same unchecked post-`run_thunk` `set_reg` pattern in `vm_raise_value`'s
continuable-handler path (`vm_state.rs:2550-2555`; no colliding repro found) and
the same truncate-after-run wind ordering in `AbortCurrentContinuation`
(`vm_state.rs:2293-2303`; unexercised). The A2 fix should sweep **every**
internal `run_thunk`/`run_loop_until` caller — the audit enumerated them and
found no others, but the sweep is the durable form of that claim.

**Acceptance for group A:** A1/A2/A3 fixed with regression tests at the exact
repro grain; the A4 sweep documented in the fix PR (list of every internal
boundary and which check guards it).

**Fixed.** A1 by making the quasiquote expanders fallible on both backends
(`CompileError::Desugar` → `VmBackendError::Desugar`; `EvalError::InvalidSyntax`
in place of `InternalError`). A2/A3/A4/C3 by one change of protocol: a
continuation invocation is reported as an *unwind*
(`VmError::ContinuationEscape` with the value parked on `pending_escape`), and
`run_loop_until_outcome` — the only place that knows an `exit_depth` — is the
only place that decides whether to resume or exit. The two ad-hoc depth tests
in `call_value_with_probe` and its tail twin are gone; they got the
`frames.len() == exit_depth` case wrong, which is why an escape into the
caller's own frame both clobbered a register and abandoned the rest of the
form. Every wind-record loop now pops before running its after-thunk. The
sweep table (every internal boundary and its guard) is the module comment of
`crates/patina-tests/tests/internal_escape_boundaries.rs`.

Two knock-on notes. A3 now *terminates* on both backends where chibi still
loops, so there is nothing left to pin — the divergence became agreement.
And the `callability.rs` divergence row for an error raised inside a wind
thunk moved from `handled` to `caught` on the VM: an unarbitrated value either
way (chibi loops), but `caught` is the explicable one — the after-thunk's own
error now reaches the enclosing `guard` instead of being swallowed by a
re-entrant unwind.

## B — Data loss and safety

### B1 `[x]` CRITICAL — `delete-file-hierarchy` dropped upstream's unsafe-directory guard

`lib/chibi/filesystem.sld:148-151`. Chibi's implementation (reference
`lib/chibi/filesystem.scm:87-99`) refuses `""` and `"/"` with "won't delete
unsafe directory" before touching anything; the hand-written Patina branch
starts deleting immediately. Verified for `""` (attempts deletion, errors on
"No such file"); for `"/"` — by code reading, obviously not executed — it would
depth-first delete every user-writable file it reaches until the first error
aborts the walk. A computed-empty path is all it takes. **Fix sketch:** restore
the one-line guard upstream deliberately carries.

### B2 `[x]` MEDIUM — `delete-file-hierarchy` ignores its `ignore-errors?` argument

Same site: the definition takes `. o` and never reads it. Chibi's signature is
`(delete-file-hierarchy dir [ignore-errors?])`; a caller passing `#t` gets an
exception exactly where it asked for tolerance.

**Acceptance for group B:** both fixed in one PR with tests; B1's test asserts
the refusal fires *before* any filesystem call.

## C — Regressions introduced in this range

### C1 `[ ]` HIGH — dotted quasiquote in a library macro no longer relinks private helpers (#68)

`crates/patina-frontend/src/desugarer/mod.rs:447-469` (`rewrite_form`).
`` `(a . ,e) `` reads as `(quasiquote (a unquote e))`; `unquote` sits in the
spine's interior, so the new spine walk treats it as an ordinary argument and
rewrites `e` at quasi depth 1 instead of 0 — a library-private helper inside
`e` is never relinked to the definition environment.

```scheme
;; library exports mq-dotted, keeps helper private:
(define (helper x) (* 5 x))
(define-syntax mq-dotted
  (syntax-rules () ((_ x) `(a . ,(helper x)))))
;; use site:
(mq-dotted 2)
;; VM => unbound variable: helper    tree-walker => Undefined variable: helper
;; chibi => (a . 10)
```

The pre-#68 walk re-read each cdr as a form, which handled this (the cdr
`(unquote e)` *is* a form there); #68 fixed `(f quote x)` but broke its dual.
The nested variant `` `((b . ,(helper x)) c) `` fails identically; the
proper-list and vector cases work. This is a sibling of the
`mark_substituted_tagged` tail-walk entry already open in the Track L PRD §6 —
the class needs sweeping, not spot-fixing.

### C2 `[ ]` HIGH — internal defines that shadow a keyword now fail to desugar (#89)

`crates/patina-frontend/src/desugarer/mod.rs` — `shadowed_names` is populated
only from lambda formals (`:887`, `:1133`), never from body definitions
(`desugar_body_tagged` `:914-969`), so `resolve_syntax` (~`:331`) sees the core
binding.

```scheme
(define (f) (define if 3) (+ if 1))
(f)
;; both backends => desugar error: invalid use of syntax as a value: 'if'
;; chibi => 4      (legal R7RS: §5.3.2 body defines shadow like letrec*)
```

Same for `(define when 3)` → "`when` is a macro". Before #89 this evaluated
correctly (no value-position check existed; the Var resolved at runtime). This
falsifies the "a missed rejection, never a wrong one" comment in
`crates/patina-tests/tests/syntax_as_a_value.rs:27-30`. The silent half is
pre-existing (D6). **Fix sketch:** scan body defines into `shadowed_names`
before resolving the body's forms — one collection pass, same as formals.

### C3 `[x]` HIGH — `call-with-values` as a value: no escape check after the producer (#87)

`vm_state.rs:2373` (`VmControlPrimitive::CallWithValues`): the producer's
`run_thunk` result is used unconditionally, so when the producer escapes, the
consumer runs anyway *with the escape value* and its result replaces it.

```scheme
(define cwv call-with-values)
(define ran 'no)
(define r (call/cc (lambda (k)
  (cwv (lambda () (k 42)) (lambda vs (set! ran 'consumer-ran) 99)))))
(write (list r ran))
;; VM => (99 consumer-ran)     tree-walker, chibi => (42 no)
```

Head position uses `Instruction::CallWithValues` and is safe. Distinct from the
pinned "primitive as call-with-values *consumer*" entry in Track L §6 (that is
the consumer-callback depth ambiguity; this is the producer boundary simply
missing its check). Fixed by the A2/A4 sweep.

### C4 `[ ]` HIGH — macro-introduced literal wrongly vetoed by a use-site shadow of the same spelling

`crates/patina-macros/src/macro_expander/matcher/literal.rs:67-72`
(`is_literal_shadowed_tagged`): the veto fires on
`shadowed_names.contains(input_name)` without checking that the *input
identifier's own scopes* resolve to that shadow, so a macro-introduced
identifier denoting the same binding as the literal is rejected.

```scheme
(define-syntax my-if2
  (syntax-rules () ((_ c t e) (cond (c t) (else e)))))
(let ((else #f)) (my-if2 #f 'wrong 'right))
;; both backends => Invalid syntax: invalid use of syntax as a value:
;;                  `else` is a syntactic keyword
;;                  (the else clause demotes to a test clause, then #89 rejects)
;; chibi, Gauche => right
```

The template-introduced `else` denotes base's `else` — same binding as `cond`'s
literal — and must match (R7RS §4.3.2). The name-only comparison may predate
#62, but #63 removed the scope-subset check that sometimes masked it, and #89
turned the mismatch into a hard error, so it regressed from wrong-but-quiet to
rejection of a legal program. Fix together with D3 — both are the same missing
"compare bindings, not spellings" step.

**Acceptance for group C:** all four fixed with the repros above as regression
tests; C1 and C2 gate the next corpus sweep (both break legal programs that
third-party libraries actually contain).

## D — Pre-existing defects exposed or made load-bearing by this range

### D1 `[ ]` HIGH — `parameterize` leaks earlier bindings when a later install fails; #70 routes all program I/O through it

`lib/scheme/base/parameters.scm:39-45`: bindings install inside
`dynamic-wind`'s *before*-thunk, so when a later binding's install raises (a
non-port for a standard port, or a raising converter), the after-thunk never
runs and the already-installed bindings are never restored. The R7RS §4.2.6
reference implementation converts and validates *before* entering the wind,
which is why chibi is immune. Newly dangerous with #70: before it,
`parameterize` on a standard port was rejected outright.

```scheme
(define sink (open-output-string))
(guard (e (#t 'caught))
  (parameterize ((current-output-port sink) (current-input-port 5)) 'body))
(display "leaked") (newline)
;; both backends: prints nothing, exit 0 — every subsequent write lands in
;; sink forever.  chibi: current-output-port restored.
```

### D2 `[ ]` HIGH — `parameterize` restore re-applies the converter to the already-converted value

`lib/scheme/base/parameters.scm:44-45`: the restore `(p old)` goes through the
setter, which converts on every call.

```scheme
(define p (make-parameter 10 (lambda (x) (* x 2))))
(p)                          ; 20
(parameterize ((p 1)) (p))   ; 2
(p)                          ; both backends => 40    chibi / R7RS => 20
```

A type-changing converter (`number->string`) makes the restore *raise*. R7RS
§4.2.6 restores the converted value without re-conversion. Fix with D1 —
pre-convert all values, install/restore raw.

### D3 `[ ]` HIGH — a keyword imported under a rename never matches a `syntax-rules` literal

`crates/patina-macros/src/macro_expander/matcher/literal.rs:93-127`: matching
is spelling-based with only the shadowing veto; the "both refer to the same
lexical binding" half of R7RS §4.3.2 is unimplemented.

```scheme
(import (scheme base) (rename (scheme base) (else alt)))
(cond (#f 1) (alt 42))
;; both backends => invalid use of syntax as a value: 'alt'
;; chibi => 42
```

Before this range the program *accidentally* printed 42 (`else` was bound to a
value; `alt` evaluated truthy), so observable behavior regressed to an error,
but the matching defect is pre-existing. Fix together with C4.

### D4 `[ ]` MEDIUM — a literal bound by the template's own binding form is treated as unbound

`crates/patina-macros/src/macro_expander/compiler/mod.rs:104-152`
(`resolve_literal_bindings`): at inner-macro compile time a template-introduced
binding for the literal is in neither the environment nor `shadowed_names`, so
`binding_scopes = None` → "both unbound" → name match.

```scheme
(define-syntax m
  (syntax-rules ()
    ((_ e) (let ((k 1))
             (let-syntax ((n (syntax-rules (k) ((n k) 'lit) ((n x) 'var))))
               (n e))))))
(m k)
;; both backends => lit      chibi AND Gauche => var
```

Related note, recorded as a divergence rather than a defect: a literal bound to
a *library-private* variable matching an unbound use-site identifier — Patina
and Gauche answer `lit`, chibi answers `var`; the references split.

### D5 `[ ]` HIGH — `eq?`/`eqv?` hash tables hash structurally; newly load-bearing via SRFI 125

`lib/srfi/69/srfi-69-impl.scm:82` (`(define hash-by-identity hash)` — upstream
text, but SRFI 125's `make-eq-comparator` path now makes identity hashing the
expected contract). Three verified consequences, both backends:

```scheme
(define ht (make-hash-table eq?))
(define k (vector 1 2 3))
(hash-table-set! ht k 'v)
(vector-set! k 0 99)
(hash-table-ref/default ht k 'MISSING)   ; => MISSING   (chibi: v)
;; procedure key  => error "hash: procedures cannot be hashed"
;; circular pair key => HANGS (unbounded recursion in hash)
```

Undocumented: neither `125.sld`'s four-deviation list nor `PROVENANCE.md`
mentions it. **Fix sketch:** a real identity hash (heap index — the collector
is non-moving, same argument `equal-hash` already relies on at
`heap/mod.rs:2213`).

### D6 `[ ]` MEDIUM — a body define of a keyword silently loses head position to the core form

The pre-existing half of C2, unfixed by #88:
`(define (g) (define if (lambda (a b c) 'shadowed)) (if 1 2 3))` → both
backends silently answer `2` (core `if` claims the head); chibi answers
`shadowed`. Same fix as C2.

### D7 `[ ]` LOW — `hash` still errors on `±inf.0` / `+nan.0` keys

`lib/srfi/69/srfi-69-impl.scm:68`: the `real?` branch calls `numerator`, which
raises (catchable). The new `exact`-wrap deviation fixed `2.0`/`2.5`/rationals
but its comment claims the whole inexact class; non-rational reals are not
covered.

**Acceptance for group D:** D1/D2 fixed as one PR (validate-then-wind); D3
with C4; D5 with the identity-hash change plus the three repro grains as tests;
D4/D6/D7 individually small.

## E — Harness trust (patina-compat)

### E1 `[ ]` HIGH — SRFI-64-style failure output classifies as pass (latent false green)

`crates/patina-compat/src/run.rs:523-530` (`test_suite_failed`) recognizes only
`(chibi test)` shapes — uppercase `FAIL`, or a digit immediately before
`" failure"`/`" error"`. The vendored SRFI-64 reference
(`compat/vendor/srfi-64/srfi/64.scm:274`) reports `# of failures  N` (count
*after* the phrase), logs per-test detail to a file, and uses lowercase.
Verified end-to-end: a deliberately failing one-test suite, run exactly as the
harness runs it, produced exit 0 and classified `Status::Pass`.

**Currently latent, not active:** the three at-risk `pass` rows (srfi-64
itself, lassik-string-inflection, arvyy-mustache) were re-run and genuinely
pass today, so the committed 143/184 is honest. The near-miss the code gets
right: srfi-64's `# of expected failures` (xfail) is correctly not a failure.
SRFI 78's `*** failed ***` shape would also be invisible (unexercised —
srfi-78 runs probe-mode only). **Fix sketch:** teach `test_suite_failed` the
srfi-64 counter line; add a failing-suite fixture to the harness tests so the
detector itself is under test.

### E2 `[ ]` MEDIUM — a `(test "file")` clause naming a missing file silently degrades the package to probe mode

`crates/patina-compat/src/corpus.rs:136-138`; a typo would silently drop a
suite with no warning. No current instance (verified: the 187→184 corpus change
is exactly the three bundled packages, openly narrated in the PRD).

### E3 `[ ]` LOW — FFI-stub classification outranks the failure check

`run.rs:419-421`: a suite with genuine FAILures that also reached an FFI stub
files as `out-of-scope`, hiding `wrong-result`. Currently unexercised (both
out-of-scope rows are missing-library-shaped).

### E4 `[ ]` LOW — `build_corpus.py --check` can never stay green

`compat/tools/build_corpus.py:454` embeds `date.today()` in MANIFEST.json, so
`--check` on any later day reports MANIFEST drift and exits 1 (verified). The
check cannot serve as a gate in this state; exclude the timestamp from the
comparison.

**Acceptance for group E:** E1 fixed with a fixture; E2–E4 batched. The
reports themselves were cross-checked clean: `report.md` re-renders
byte-identical from `results.scm`; no hand-editing; no silent test→probe
flips across the range.

## F — Minor correctness, diagnostics, and documentation

### F1 `[ ]` MEDIUM — filesystem primitives raise where chibi returns `#f`/`'()`; deviation undocumented

`crates/patina-primitives/src/primitives/io/directory.rs:36-38` maps every
failure to a raised `IOError`. Chibi's `create-directory`/`delete-directory`/
`change-directory` return `#f` on failure and `directory-files` returns `'()`
on an unreadable directory. Everything is catchable and panic-free (verified),
but chibi-ecosystem code branching on `#f` — including upstream's own
`create-directory*` idiom — gets exceptions. Either match chibi or record the
deviation in `filesystem.sld`'s header and `lib/chibi/PROVENANCE.md`.

### F2 `[ ]` LOW — `make-hash-table` weakness arguments silently ignored

`lib/srfi/125/hash.scm:7-11` drops the rest args; SRFI 125 says an error
should be signaled for unsupported weakness. Matches chibi upstream, but is
not among the sld's declared deviations — declare it or signal.

### F3 `[ ]` MEDIUM — a malformed *known* library declaration is swallowed as "unknown" (#61)

`crates/patina-frontend/src/library_parser.rs:155-168, 252-268`: the skip
fires on list shape before seeing the keyword, so `(export . go)` warns
`ignoring unknown library declaration 'pair'` and silently drops the export;
the importer later gets an unrelated "unbound variable". The lenient policy
itself works as designed (`PATINA_STRICT_LIBRARY_SYNTAX=1` rejects). Improve
the diagnostic: name the keyword when the head is recognizable.

### F4 `[ ]` LOW — body-position `define-syntax` recognized by spelling, ignoring shadows

`desugarer/mod.rs:989` (`try_parse_define_syntax_tagged`) — the exact class
#88 removed for every other keyword. Contrived repro; fold into the C2 fix.

### F5 `[ ]` LOW — BOM and invisible characters lex as identifiers

`crates/patina-frontend/src/lexer/mod.rs:841-843`: a leading U+FEFF, ZWSP,
soft hyphen, bidi controls, or C1 controls now silently start identifiers,
yielding "unbound variable" errors whose names render invisibly. Consistent
with chibi's any-above-ASCII rule, so arguably by design — strip a leading BOM
and name invisible code points in diagnostics.

### F6 `[ ]` MEDIUM — pin: tree-walker `call-with-port` closes the port when an in-extent continuation invoke is misread as an escape

Repro: a call/cc retry loop inside a `call-with-port` callback — VM/chibi
`"012"`, tree-walker "port is closed" (premature close at
`io/ports.rs:659`). Root cause is the already-pinned tree-walker
nested-trampoline defect; this resource-corruption manifestation is not
recorded. Add to `backend_divergence.rs`, alongside A3's three-way split.

### F7 `[ ]` LOW — `if let Ok(lib) = load_scheme_library(…)` discards a possible escape

`crates/patina-primitives/src/primitives/eval.rs:530, 542`: if the discarded
`Err` were `ContinuationEscape`, the parked `pending_escape` would be misread
on the *next unrelated error*. Unreachable today (no user code runs while
loading `(scheme inexact)`/`(scheme complex)`), but it is the only
sentinel-protocol break found in the sweep of every `apply_proc`/`eval_expr`
site. Propagate the error.

### F8 `[ ]` LOW — VFS latent semantic gaps (test lanes only; the binary uses NativeFs)

`crates/patina-core/src/vfs.rs:482` — `OverlayFs::read_dir` uses
`unwrap_or_default()` on the overlay, hiding overlay-written files in
base-only directories; `:501-512` — `create_dir`/`set_current_dir` consult the
overlay only, contradicting the merged read side; MemoryFs `create_dir_all`
never fails and permits a file and directory at the same path. No unit tests
cover the new directory API.

### F9 `[ ]` LOW — documentation drift found while auditing

- `PRD/TRACK_L_SNOW_LIBRARIES_PRD.md:721` — "VM: a raising parameter converter
  produces no output at all", marked open, no longer reproduces (evidently
  fixed by #73/#77): mark fixed.
- `compat/vendor/LICENSES.md:151` (and `:78`) — hand counts stale since the
  two BSD chibi packages left the corpus (BSD 63→61, SLIB 45→44).
- Guard re-raise does not rewind into the raiser's dynamic extent (strict
  R7RS §4.2.7 reading; chibi re-enters). Pre-existing nuance, observable only
  with side-effecting wind thunks — record as a known deviation.

Recorded so the next audit doesn't re-plow it — each item was tested, not
assumed, on both backends:

  case-fold edge; EOF/near-miss inputs; no over-read). #65/#82 are pure
  widenings; `,@` tokenization, `|@|` round-trip, `#\λ`, 4-byte UTF-8, and a
  78-file fuzz produced zero panics and zero divergences (the lexer is fully
  `Vec<char>`-indexed).
