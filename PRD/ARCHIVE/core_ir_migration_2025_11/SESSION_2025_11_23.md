### 2. Created `MacroEnv` Type ✅

**File:** `crates/patina-macros/src/macro_env.rs`

**Purpose:** Dedicated environment for macro definitions, separate from runtime `Environment`

```rust
pub struct MacroEnv {
    /// Macro definitions (name -> compiled macro)
    macros: HashMap<Rc<str>, CompiledMacro>,

    /// Parent environment for nested scopes
    parent: Option<Rc<MacroEnv>>,
}
```

**Key features:**
- Stores only macro definitions (not runtime bindings)
- Supports nested scopes with parent chains (for lexical scoping)
- Clean API: `define_macro()`, `lookup_macro()`, `is_macro()`, `extend()`

## Hygiene Discussion

**User question:** Will this make fixing the `let-syntax` hygiene bug harder?

**Answer:** NO - it makes it EASIER! Here's why:

**The bug:**
```scheme
(let ((x 'outer))
  (let-syntax ((m (syntax-rules () ((m) x))))
    (let ((x 'inner))
      (m))))

;; Expected: 'outer (macro should capture x from outer let)
;; Actual:   'inner (macro uses wrong x)
```

**Why MacroEnv helps:**
- `MacroEnv` has parent chains for lexical scoping
- We can capture the `MacroEnv` at macro definition time
- Store it with the `CompiledMacro`
- Use it during template expansion to resolve free identifiers

**Fix strategy documented in:** `docs/MACRO_ARCHITECTURE_DECISIONS.md`
